# Who married who? — Canada

A local, interactive prototype for exploring spouse occupations by selected occupation and gender.

## Run

Requires Node.js 22.12+ (or a current supported release).

```sh
npm install
npm run dev
```

Open the local URL printed by Vite. `npm run build` type-checks and creates `dist/`. `npm run preview` serves the production build.

## Recommended stack

- React + TypeScript for state, accessible controls, and explicit data types.
- Vite for a small static build with no backend requirement.
- SVG for this bounded connection diagram; consider D3 only if a full draggable network is required.
- Local JSON summaries for a first Canada-wide release. At larger scale, partition by geography or serve summaries from SQLite through an API.
- A separate Python/Polars or DuckDB preparation pipeline for eventual census extraction, spouse matching, validation and aggregation. Not implemented in this prototype.
- Static hosting (Cloudflare Pages, Netlify, or equivalent) when ready. Nothing has been deployed.

## Data: illustrative only

`src/demo-data.json` is a deterministic synthetic fixture. No percentages represent actual Canadian marriages. Gender choices do not assert that equivalent census categories are available. No real microdata, personal information, source API or external database is included.

The fixture represents unordered couples using profile indices `a` and `b` and an illustrative `weightedCount`. Counts are generated by `10 + ((a+3)*97 + (b+7)*53 + (a+1)*(b+1)*19) % 390` for every `a <= b`. This has no demographic meaning. Every selection works; no relationship patterns are inferred from actual observations.

The calculation counts matching people in each couple. A couple whose two profiles both match contributes twice, since both people meet the selection. Shares sum to 100% before rounding. All spouse genders and no-recorded-occupation categories remain in the denominator. The graph shows the six largest combinations and aggregates the remainder; the full list exposes all combinations. It does not filter on province, age or relationship type.

## Path to real data

Candidate: https://www150.statcan.gc.ca/n1/en/catalogue/98M0001X2021002

Before replacing the fixture:

1. Obtain the data dictionary and confirm spouse linkage, occupation granularity, available gender categories, and target population. Do not pair all adults sharing a household; identify actual spouses within census families.
2. Confirm the correct weighting unit and treatment of marriages, common-law couples, missing occupations and co-residence. Adapt the current schema if source weights require person-specific directional totals.
3. Produce validated weighted counts plus unweighted sample sizes and relevant uncertainty measures. Enforce source publication and disclosure requirements. Suppressed values must not be represented as zero or recovered from totals.
4. Verify totals against published benchmarks. Decide which categories are sufficiently reliable to display.
5. Export only aggregate data; record source, year, universe, classification, denominator, weighting and suppression metadata.
6. Replace all prototype labels only after source and calculations are independently verified.

The interface intentionally labels synthetic results throughout. The current graph is a static-layout network with list-driven highlighting, rather than a free-form force simulation. On narrow screens the diagram scrolls horizontally to preserve labels, while the ranked list fits the viewport. Fonts are loaded from Google Fonts with local fallbacks; the data itself is bundled locally.
